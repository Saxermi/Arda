# Tensor structure, differentiation and mathematical documentation

**Status** — Candidates for 0.15–0.17, 0.22–0.24 and mathematical reporting. The [scalar AD and tensor storage notes](../README.md) cover current implementations.

| Capability | Baseline and alternatives | Cost, reliability and implementation plan |
| --- | --- | --- |
| Compressed tensors and structured operators | Represent a low-rank matrix as $UV^T$. Compare CP, Tucker/HOSVD and tensor trains, beginning with explicit factor or core construction and deterministic TT-SVD on suitable data. TT-cross and randomized rounding are experimental. Structured band, diagonal and Kronecker operators should apply directly. | A rank-$r$ matrix takes $O((m+n)r)$ storage and apply work. A uniform rank-$r$ TT with $d$ modes of size $n$ takes $O(dnr^2)$ storage. Actual TT-SVD cost depends on intermediate unfoldings. Tucker core size grows with the product of retained ranks. Measure reconstruction, rounding error and actual peak RSS. CP fitting can be ill-conditioned and nonconvex. Moderate CPU effort for factor applies, high for robust truncation and contraction planning. |
| Tensor AD, JVPs, VJPs and replay | Start with a reverse tape, broadcast-aware gradient reduction and versioned alias tracking. Add forward JVPs for few directions, checkpoint replay for pure operations and selected solver adjoints after residual validation. | Reverse mode has arithmetic cost comparable to a small multiple of the forward graph for supported primitives, plus accumulation, with live storage dominated by saved intermediates. Checkpointing trades recomputation and possible I/O for retention. Test tape lifetime, mutation, broadcast adjoints, finite differences, dot-product adjoint identities and independent references. Moderate CPU effort initially, high for offloading and replay across stateful primitives. |
| Structure, symbols and finite-precision contracts | First extract a typed expression tree and static descriptors. Add bounded, guarded rewrites for identities and derivatives. Equality saturation is an optional experiment for cost-based rewrites with explicit domain and floating-point constraints. | Direct traversal costs $O(V+E)$ for a bounded expression DAG. Rewrite search can grow rapidly and needs node/iteration limits. Check binding, assumptions, unsupported expressions, and branch and effect semantics. A rewrite can preserve real arithmetic while changing NaN, signed-zero or rounding behavior. Test static nonexecution and no overhead in ordinary kernels. |
| Intervals, units, verification and uncertainty | Begin with dimension vectors, explicit affine temperature units and first-order propagation $\Sigma_y\approx J\Sigma_xJ^T$. Compare shared-covariance approximations, seeded Monte Carlo, and outward-rounded interval arithmetic for enclosures. | Dense covariance may need $O(n^2)$ storage. Interval primitives have bounded per-operation work but dependency and wrapping can inflate bounds. Branches and rounding modes require careful handling. Check known unit transforms, covariance and correlated inputs, and enclosures against independent high precision and edge cases. Portable interval guarantees require high effort across compilers and hardware. |

**Research evidence** — Deterministic tensor factorization is the CPU baseline. Randomized TT rounding with Khatri–Rao products warrants comparison against deterministic rounding across rank and error regimes. Differentiation and checkpointing have distinct runtime and memory contracts. The 2026 application study offers a comparator for differentiable scientific kernels under a different compiler. Use exact or high-precision validation before extending symbolic transformations to numerically sensitive code. [Kolda and Bader](https://doi.org/10.1137/07070111X) · [Oseledets](https://doi.org/10.1137/090752286) · [Randomized TT rounding 2026](https://doi.org/10.1137/25M181708X) · [Checkpointing](https://arxiv.org/abs/1604.06174) · [DJ4Earth 2026](https://doi.org/10.1029/2025MS005615) · [Equality saturation](https://doi.org/10.1145/3434304) · [Interval analysis](https://doi.org/10.1137/1.9780898717716) · [Measurement uncertainty](https://doi.org/10.59161/JCGM100-2008E)

**Rights** — Document mathematical identities in original expressions. Review code and representations before importing a rewrite engine, interval backend or test corpus. Keep generated metadata out of the runtime until its semantics and cost are defined. Screen concrete novel compiler and compression mechanisms before integration.
