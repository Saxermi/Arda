# Dense linear algebra and reductions

**Status** — Dense solves and reductions were already implemented in 0.14.3. Reusable factorizations are implemented in the 0.15 development checkout. Work and storage below exclude inputs unless specified. View packing can allocate a copy of each non-contiguous operand.

## Gaussian elimination and external LAPACK

`nc.solve(A,b)` solves a finite square dense system by Gaussian elimination with partial row pivoting. At column $k$ it chooses $p=\arg\max_{i\ge k}|a_{ik}|$, swaps the remaining row segment and right-hand side, then uses $\ell_{ik}=a_{ik}/a_{kk}$ and $a_{ij}\gets a_{ij}-\ell_{ik}a_{kj}$. It back-substitutes $x_i=(b_i-\sum_{j>i}a_{ij}x_j)/a_{ii}$, accumulating that inner subtraction in `long double`. Work is $O(n^3)$ and a copied matrix plus solution cost $O(n^2)$ storage. The one-shot interface returns only the solution. It shares the partial-pivoted LU kernel with the reusable API. Neither interface estimates conditioning or performs refinement. An exact-zero pivot is rejected. Partial pivoting controls multipliers and usually yields a small backward error, subject to growth in the elimination. An ill-conditioned matrix can produce a large forward error despite a small residual. [One-shot entry point](../../src/scientific.c) · [Pivoted LU kernel](../../src/linalg.c) · [Wilkinson 1961](https://doi.org/10.1145/321075.321076) · [Higham 2002](https://doi.org/10.1137/1.9780898718027)

`calc.lapack_solve` can call `dgesv`, which uses pivoted LU and triangular solves. `calc.eigh` checks exact symmetry and calls `dsyev` in eigenvector mode for $A Q=Q\Lambda$. The reference LAPACK driver reduces to symmetric tridiagonal form then solves that eigenproblem and back-transforms eigenvectors. Arda copies to column-major storage, checks `INFO` and queries the eigensolver workspace. The square solve and eigenvectors each take $O(n^3)$ work and $O(n^2)$ storage including the copies and outputs. Eigenvectors in clustered eigenspaces can be sensitive and are assessed by residual, orthogonality and subspace agreement. The concrete kernels depend on the provider chosen at link time. ## Reusable Float64 factorizations

Import `linalg` as `la`. Each factor owns a snapshot of a dense rank-two Float64 tensor, including a packed copy for strided inputs. `la.parts(f)` returns independent copies. `la.solve(f,b)` accepts a finite vector or a rank-two array whose columns are right-hand sides. Solves and part extraction preserve the stored factor. The examples use all three methods. [Implementation](../../src/linalg.c) · [Example](../../examples/factorizations.arda)

| API | Returned parts | Solve and constraints |
| --- | --- | --- |
| `la.lu(A)` | `[p,L,U]`, with zero-based row permutation `p` satisfying $A[p,:]=LU$ | Partial pivoting for a square matrix. Apply the permutation to each right-hand side, followed by forward and backward triangular substitution. Zero pivots and nonfinite factor entries raise errors. |
| `la.cholesky(A)` | `[L]`, with $A=LL^T$ | Square, exactly symmetric matrices with positive computed pivots. Solve with $L$ and $L^T$. Nonsymmetric input and nonpositive pivots raise errors. |
| `la.qr(A)` | `[Q,R]` in reduced form, with $A=QR$ and $Q^TQ=I$ | The factorization also accepts wide matrices. Least-squares solve requires at least as many rows as columns and checks numerical full column rank before applying $Q^T$ and solving with $R$. |

LU and Cholesky use $O(n^3)$ factorization work and $O(n^2)$ packed storage. A solve with $p$ right-hand sides costs $O(n^2p)$ work. LU stores a unit-lower triangle and an upper triangle in one array. Cholesky builds the lower triangle using $L_{ij}=(A_{ij}-\sum_{k<j}L_{ik}L_{jk})/L_{jj}$ off the diagonal and takes the square root of the diagonal update. Cholesky needs the SPD contract and can reject a nearly singular input when rounding results in a nonpositive pivot. It requires exact input symmetry. [Accuracy and Stability of Numerical Algorithms](https://doi.org/10.1137/1.9780898718027) · [LAPACK factorization guidance](https://www.netlib.org/lapack/lug/node37.html)

QR stores the Householder reflectors $H_k=I-\tau_k v_kv_k^T$ below the diagonal of the packed array, with an implicit leading one in each reflector. It scales the active column before computing the reflector and applies reflectors to compute $Q^Tb$ without forming $Q$. Let $k=\min(m,n)$. Factorization takes $O(mnk)$ work and $O(mn+k)$ storage, and extracting $Q$ and $R$ allocates $O(mk+kn)$ additional storage. A tall solve with $p$ right-hand sides takes $O(mnp)$ work and $O(mp+np)$ storage including work and output. The rank check compares $|R_{ii}|/\max_j |R_{jj}|$ against $m\epsilon$ for Float64. This is a screening heuristic for the unpivoted solve, with rank-revealing factorization and condition estimation still future work. [Householder 1958](https://doi.org/10.1145/320941.320947) · [LAPACK DGEQRF](https://www.netlib.org/lapack/explore-html/d0/da1/group__geqrf_gade26961283814bb4e62183d9133d8bf5.html)

The portable kernels use original code based on the classical formulas and the documented packed representations. LAPACK and SciPy serve as documentation and validation references. Recent randomized CholeskyQR work addresses tall matrices and different performance regimes. Arda starts with Householder reflectors to handle general shapes and avoid explicitly forming $A^TA$. [Rationale](../../DECISIONS.md#2026-11-24--portable-reusable-dense-factorizations) · [Guan et al. 2026](https://arxiv.org/abs/2607.15561)

## Dense products and reductions

`nc.matmul` computes $C_{ij}=\sum_k A_{ik}B_{kj}$ in $O(mkn)$ time with $O(mn)$ output and constant local native workspace on packed inputs. The default path uses row-major blocking, scalar tails, and SSE2 or runtime-dispatched AVX2 when available. The optional CBLAS build calls `cblas_dgemm`. Float64 sums are rounding-sensitive and backend order or contraction can affect results. See the kernel note for dispatch details and the 0.18 baseline. [Source, `multiply` and `matmul_avx2`](../../src/scientific.c) · [Lawson et al. 1979](https://doi.org/10.1145/355841.355847) · [Goto and van de Geijn 2008](https://doi.org/10.1145/1356052.1356053) · [Kernel details](transforms-and-kernels.md)

`nc.dot` and `high.inner` use four extended-precision accumulators for $x^Ty$. `nc.sum`, `nc.mean` and `high.sum_axis` use extended accumulation with no compensated summation guarantee. The portable norm scales the sum of squares, evaluating $s\sqrt{\sum_i(x_i/s)^2}$ with a running scale $s$ so the initial squaring does not cause needless overflow or underflow. Variance uses Welford's online recurrence $\delta_i=x_i-\mu_{i-1}$, $\mu_i=\mu_{i-1}+\delta_i/i$, $M_{2,i}=M_{2,i-1}+\delta_i(x_i-\mu_i)$. The returned variance is the population value $M_{2,n}/n$ and standard deviation its square root. These use $O(n)$ time and $O(1)$ scalar scratch, plus any packed input or axis output. Streaming updates mitigate cancellation in the naïve second-moment formula. The actual precision of `long double` is platform dependent. Min/max are scans, `linspace` interpolates endpoints, and elementwise sin, cos, exp, log and sqrt delegate to the platform math library.
