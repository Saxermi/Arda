# Dense linear algebra and reductions

**Status** — Dense solves and reductions were already implemented in 0.14.3. Arda 0.15.0 adds reusable factorizations, dense utilities, and structured direct solvers. Work and storage below exclude inputs unless specified. View packing can allocate a copy of each non-contiguous operand. [Release validation](../../docs/RUMIL_0.15.0.md)

## Gaussian elimination and external LAPACK

`nc.solve(A,b)` solves a finite square dense system by Gaussian elimination with partial row pivoting. At column $k$ it chooses $p=\arg\max_{i\ge k}|a_{ik}|$, swaps the remaining row segment and right-hand side, then uses $\ell_{ik}=a_{ik}/a_{kk}$ and $a_{ij}\gets a_{ij}-\ell_{ik}a_{kj}$. It back-substitutes $x_i=(b_i-\sum_{j>i}a_{ij}x_j)/a_{ii}$, accumulating that inner subtraction in `long double`. Work is $O(n^3)$ and a copied matrix plus solution cost $O(n^2)$ storage. The one-shot interface returns only the solution. It shares the partial-pivoted LU kernel with the reusable API. Neither interface estimates conditioning or performs refinement. An exact-zero pivot is rejected. Partial pivoting controls multipliers and usually yields a small backward error, subject to growth in the elimination. An ill-conditioned matrix can produce a large forward error despite a small residual. [One-shot entry point](../../src/scientific.c) · [Pivoted LU kernel](../../src/linalg.c) · [Wilkinson 1961](https://doi.org/10.1145/321075.321076) · [Higham 2002](https://doi.org/10.1137/1.9780898718027)

`calc.lapack_solve` can call `dgesv`, which uses pivoted LU and triangular solves. `calc.eigh` checks exact symmetry and calls `dsyev` in eigenvector mode for $A Q=Q\Lambda$. The reference LAPACK driver reduces to symmetric tridiagonal form then solves that eigenproblem and back-transforms eigenvectors. Arda copies to column-major storage, checks `INFO` and queries the eigensolver workspace. The square solve and eigenvectors each take $O(n^3)$ work and $O(n^2)$ storage including the copies and outputs. Eigenvectors in clustered eigenspaces can be sensitive and are assessed by residual, orthogonality and subspace agreement. The concrete kernels depend on the provider chosen at link time. ## Reusable Float64 factorizations

Import `linalg` as `la`. Each factor owns a snapshot of a dense rank-two Float64 tensor, including a packed copy for strided inputs. `la.parts(f)` returns independent copies. `la.solve(f,b)` accepts a finite vector or a rank-two array whose columns are right-hand sides. Solves and part extraction preserve the stored factor. The examples use all three methods. [Implementation](../../src/linalg.c) · [Example](../../examples/factorizations.arda)

| API | Returned parts | Solve and constraints |
| --- | --- | --- |
| `la.lu(A)` | `[p,L,U]`, with zero-based row permutation `p` satisfying $A[p,:]=LU$ | Partial pivoting for a square matrix. Apply the permutation to each right-hand side, followed by forward and backward triangular substitution. Zero pivots and nonfinite factor entries raise errors. |
| `la.cholesky(A)` | `[L]`, with $A=LL^T$ | Square, exactly symmetric matrices with positive computed pivots. Solve with $L$ and $L^T$. Nonsymmetric input and nonpositive pivots raise errors. |
| `la.qr(A)` | `[Q,R]` in reduced form, with $A=QR$ and $Q^TQ=I$ | The factorization also accepts wide matrices. Least-squares solve requires at least as many rows as columns and checks numerical full column rank before applying $Q^T$ and solving with $R$. |

LU and Cholesky use $O(n^3)$ factorization work and $O(n^2)$ packed storage. A solve with $p$ right-hand sides costs $O(n^2p)$ work. LU stores a unit-lower triangle and an upper triangle in one array. Cholesky builds the lower triangle using $L_{ij}=(A_{ij}-\sum_{k<j}L_{ik}L_{jk})/L_{jj}$ off the diagonal and takes the square root of the diagonal update. Cholesky needs the SPD contract and can reject a nearly singular input when rounding results in a nonpositive pivot. It requires exact input symmetry. [Accuracy and Stability of Numerical Algorithms](https://doi.org/10.1137/1.9780898718027) · [LAPACK factorization guidance](https://www.netlib.org/lapack/lug/node37.html)

QR stores the Householder reflectors $H_k=I-\tau_k v_kv_k^T$ below the diagonal of the packed array, with an implicit leading one in each reflector. It scales the active column before computing the reflector and applies reflectors to compute $Q^Tb$ without forming $Q$. Let $k=\min(m,n)$. Factorization takes $O(mnk)$ work and $O(mn+k)$ storage, and extracting $Q$ and $R$ allocates $O(mk+kn)$ additional storage. A tall solve with $p$ right-hand sides takes $O(mnp)$ work and $O(mp+np)$ storage including work and output. The rank check compares $|R_{ii}|/\max_j |R_{jj}|$ against $m\epsilon$ for Float64. This is a screening heuristic for the unpivoted solve, with rank-revealing factorization and condition estimation still future work. [Householder 1958](https://doi.org/10.1145/320941.320947) · [LAPACK DGEQRF](https://www.netlib.org/lapack/explore-html/d0/da1/group__geqrf_gade26961283814bb4e62183d9133d8bf5.html)

The portable kernels use original code based on the classical formulas and the documented packed representations. LAPACK and SciPy serve as documentation and validation references. Recent randomized CholeskyQR work addresses tall matrices and different performance regimes. Arda starts with Householder reflectors to handle general shapes and avoid explicitly forming $A^TA$. [Rationale](../../DECISIONS.md#2026-11-24--portable-reusable-dense-factorizations) · [Guan et al. 2026](https://arxiv.org/abs/2607.15561)

## Dense matrix utilities

- `la.det(A)` computes $\det(A)=\operatorname{sign}(P)\prod_i U_{ii}$ from one pivoted LU of a square matrix. It tracks permutation parity and normalizes the mantissa/exponent product so intermediate products can cross the Float64 range. An exact zero LU pivot returns zero, a determinant beyond the finite Float64 range raises an error, and a tiny result can underflow to zero. The empty determinant is one. Near singularity, the determinant can be sensitive to roundoff.
- `la.inv(A)` uses one pivoted LU and solves $AX=I$ column by column using the same triangular substitution code as the reusable LU API. It initializes the permuted identity directly in the result and raises an error for a singular matrix. Use `la.solve` for ordinary systems when the inverse itself is unnecessary.
- `la.trace(A)` sums $\sum_i A_{ii}$ with extended accumulation. `la.diag(A)` returns a new Float64 vector of entries $A_{ii}$. Both read the strides directly, accept rectangular rank-two inputs, and inspect $k=\min(m,n)$ finite diagonal entries. An empty diagonal gives trace zero and an empty vector.

Determinant and inverse cost $O(n^3)$ work and $O(n^2)$ storage, including the copied factor and any matrix output. Trace and diagonal extraction cost $O(k)$ work with constant trace workspace and $O(k)$ storage for the extracted diagonal. Regression checks cover pivot parity, zero pivots, scaled products and empty shapes. The reference tests include strided ill-conditioned input and both left and right inverse residuals. ## Structured direct solvers

`la.solve_tridiag(lower, diagonal, upper, b)` accepts rank-one Float64 tensors of lengths $n-1,n,n-1$ for a nonempty system. The empty system accepts three empty tensors. Each row must satisfy $|d_i|>|l_i|+|u_i|$, with missing edge entries treated as zero. This sufficient condition enables elimination without pivoting. Rows are normalized by their diagonals so large changes in row scale do not produce large unscaled elimination multipliers. The method sweeps forward with $p_i=1-(l_i/d_i)c_{i-1}$ and $c_i=(u_i/d_i)/p_i$, dividing the updated right-hand side by $p_i$. Back substitution uses the stored $c_i$. A nonpositive computed pivot or nonfinite result raises an error. With $r$ right-hand sides, the work is $O(n(1+r))$ and the additional storage is one $O(n)$ work vector and the $O(nr)$ output. [Stability reference](https://doi.org/10.1137/1.9780898718027)

`la.solve_banded(l, u, bands, b)` accepts nonnegative integer bandwidths and a rank-two tensor of shape `[l+u+1,n]`. Store $A_{ij}$ at `bands[u+i-j,j]`. Corner padding is ignored. It uses Gaussian elimination with partial row pivoting within the lower bandwidth, applies each row operation to the right-hand sides, and back-substitutes through the upper band. The work array reserves up to $l$ additional superdiagonals for fill after swaps. With $w=1+l+u$, storage is $O(n(w+r))$ and work is $O(nw(1+l+r))$. Both sizes are linear in $n$ for fixed bandwidth and right-hand-side count. The work array is subject to Arda's existing tensor element cap. A zero pivot raises a singularity error and an unrepresentable intermediate or answer raises a numerical error. [LAPACK DGBSV](https://www.netlib.org/lapack/explore-html/db/df8/group__gbsv_gaff55317eb3aed2278a85919a488fec07.html)

Both APIs accept a matching vector or a matrix with right-hand sides in columns, including strided views, and preserve their inputs. The banded solver handles cases that need pivoting, including tridiagonal matrices stored with $l=u=1$. The reference tests include zero and small first pivots, upper-only and lower-only bands, asymmetric widths, and row scaling across $10^{-120}$ to $10^{120}$ for Thomas. In the scaled case, the reference uses the same row equilibration before calling SciPy. These are original serial kernels informed by classical methods and the documented band convention. Parallel narrow-band algorithms are a separate candidate whose benefit depends on hardware and problem size. [Design decision](../../DECISIONS.md#2026-11-24--guarded-tridiagonal-and-pivoted-band-solves) · [A-Rahman and di Mare 2026](https://doi.org/10.1016/j.cam.2025.117254)

## Local direct-solver benchmark

Run `make arda` followed by `python3 benchmarks/direct_linalg_bench.py --rounds 7`. This run used one pinned logical CPU on an Intel Xeon Platinum 8573C, GCC 14.2 with `-O2`, Arda's portable build, SciPy 1.17.0 and NumPy 2.3.5. The harness sets one BLAS thread, warms up each case, and reports the median of seven mean per-call times. Timed calls include their allocations and input checks. Input construction and result verification are outside the timed interval. The two tridiagonal rows for the banded comparison use Arda's guarded Thomas method and SciPy's pivoted tridiagonal solver. The general dense row represents the existing `nc.solve` approach to that same $n=512$ tridiagonal system.

## Dense products and reductions

`nc.matmul` computes $C_{ij}=\sum_k A_{ik}B_{kj}$ in $O(mkn)$ time with $O(mn)$ output and constant local native workspace on packed inputs. The default path uses row-major blocking, scalar tails, and SSE2 or runtime-dispatched AVX2 when available. The optional CBLAS build calls `cblas_dgemm`. Float64 sums are rounding-sensitive and backend order or contraction can affect results. See the kernel note for dispatch details and the 0.18 baseline. [Source, `multiply` and `matmul_avx2`](../../src/scientific.c) · [Lawson et al. 1979](https://doi.org/10.1145/355841.355847) · [Goto and van de Geijn 2008](https://doi.org/10.1145/1356052.1356053) · [Kernel details](transforms-and-kernels.md)

`nc.dot` and `high.inner` use four extended-precision accumulators for $x^Ty$. `nc.sum`, `nc.mean` and `high.sum_axis` use extended accumulation with no compensated summation guarantee. The portable norm scales the sum of squares, evaluating $s\sqrt{\sum_i(x_i/s)^2}$ with a running scale $s$ so the initial squaring does not cause needless overflow or underflow. Variance uses Welford's online recurrence $\delta_i=x_i-\mu_{i-1}$, $\mu_i=\mu_{i-1}+\delta_i/i$, $M_{2,i}=M_{2,i-1}+\delta_i(x_i-\mu_i)$. The returned variance is the population value $M_{2,n}/n$ and standard deviation its square root. These use $O(n)$ time and $O(1)$ scalar scratch, plus any packed input or axis output. Streaming updates mitigate cancellation in the naïve second-moment formula. The actual precision of `long double` is platform dependent. Min/max are scans, `linspace` interpolates endpoints, and elementwise sin, cos, exp, log and sqrt delegate to the platform math library. [`scientific_call` and `dot`](../../src/scientific.c) · [`high_call` and `linear_dot`](../../src/highdim.c) · [Welford 1962](https://doi.org/10.1080/00401706.1962.10490022) · [Anderson 2017](https://doi.org/10.1145/3061665)
